# 불 끄고 퇴근해! — 제한 시간·월세·퇴근 룰렛 규칙

기준일: **2026-10-14, 한국 시간**  
대상: 기존 `TurnOffTheLight` Unity 프로젝트의 월세 MVP  
범위: Unity 구현과 문서. 실행 파일 빌드, Notion 수정, GitHub 푸시는 수행하지 않습니다.

## 1. 플레이어의 목표

플레이어는 건물의 불을 끄며 돈을 버는 야간 근무자이며, 밀린 월세를 갚아야 합니다. 단계가 올라가면 건물과 월세가 커집니다. **각 단계에 주어진 5회 근무 안에 월세를 납부하는 것**이 목표입니다.

기본 플레이는 WASD·방향키 자유 이동과 접촉 소등입니다. 방 클릭, 점프, 중력, 계단 조작은 사용하지 않습니다. 초기 3층 건물은 비교적 느린 이동으로도 제한 시간 안에 모든 불을 끌 수 있는 난이도를 목표로 합니다.

## 2. 근무 기회와 제한 시간

1. 새 단계에서 5회 기회를 받습니다.
2. 근무 시작 시 그 단계의 방과 제한 시간을 초기화합니다.
3. 방에 닿거나 지나가면 불이 꺼지고 이번 근무 수입에 보상을 누적합니다.
4. 모든 불을 끄거나 제한 시간이 끝나면 근무를 종료하고 **기회를 정확히 1회 차감**합니다.
5. 자동화·예약 전파를 종료해 마감 후 수입이 추가되지 않도록 합니다.
6. 퇴근 정산 후 월세 납부, 강화, 다음 근무를 선택합니다.

완료 여부와 상관없이 기회가 차감됩니다. 시간이 끝나면 아직 켜진 전등이 있어도 근무에 복귀할 수 없습니다. 다음 기회를 선택하면 같은 단계의 새 건물 근무를 시작하며 잔고와 강화를 유지합니다.

설정·업무 안내·스킬 트리는 이동과 제한 시간을 일시 정지합니다. 퇴근 정산과 룰렛 동안에도 근무는 멈춥니다. 정산 화면에서 T·ESC를 눌러 이미 종료된 근무의 시간이나 기회를 복구할 수 없습니다.

## 3. 초기 성장 수치

현재 수치는 구현 검증을 위한 MVP 기본값입니다. 출시 밸런스로 확정하지 않았습니다.

| 항목 | 1단계 | 2단계 |
| --- | ---: | ---: |
| 층수 | 3 | 5 |
| 층당 전등 | 4 | 4 |
| 전체 전등 | 12 | 20 |
| 제한 시간 | 30초 | 30초 |
| 근무 기회 | 5회 | 5회 |
| 월세 | 160 | 273 |
| 기본 보상 전체 소등 수입 | 61.5 | 105 |

층수 순서: **3 → 5 → 8 → 12 → 18 → 28 → 42 → 64 → 96 → 144 → 216 → 300**. 이후에도 층수는 300으로 제한합니다.

현재 모델의 산정 규칙은 다음과 같습니다.

- 제한 시간: `min(80, 30 + max(0, 단계 - 2) × 5)`초. 처음 두 단계는 30초, 3단계부터 5초씩 늘어납니다.
- 0부터 시작하는 층 `f`의 기본 전등 보상: `5 + 0.125 × f`.
- 기본 전체 소등 수입: `4 × 층수 × (5 + 0.125 × (층수 - 1) / 2)`.
- 월세: 기본 전체 소등 수입에 `2.6 + max(0, 단계 - 12) × 0.08`을 곱한 뒤 올림.
- 이동 보너스와 룰렛으로 실제 수입을 늘릴 수 있지만, 월세 기준은 기본 전체 소등 수입으로 산정합니다.

가격·시간·월세를 수정하려면 `LightsOutRentModel`의 해당 함수와 검사 기준을 함께 확인해야 합니다.

## 4. 보유금과 이번 근무 수입

두 금액을 분리합니다.

| 금액 | 의미 | 사용할 수 있는 시점 |
| --- | --- | --- |
| 보유금 `Work.Money` | 이전 정산으로 받은 잔고 | 월세 납부·강화 구매 |
| 미정산 수입 `Work.PendingIncome` | 현재 근무에서 새로 번 돈 | 근무 종료 후 정산 선택 |

미정산 수입은 근무 도중 강화에 사용할 수 없습니다. 정산되지 않은 돈을 먼저 써서 룰렛의 손실을 회피하는 흐름을 차단합니다. 기존 보유금은 근무 중에도 강화에 사용할 수 있습니다.

퇴근 정산에서 **그대로 받기 ×1** 또는 **퇴근 룰렛** 중 하나만 선택합니다. 선택한 지급액을 보유금에 한 번 더하고 미정산 수입을 정리합니다. 같은 근무를 중복 정산하지 않습니다.

예: 기존 보유금 20, 이번 수입 30일 때 그대로 받으면 보유금 50입니다. 룰렛 ×0이면 기존 20이 남으며, ×2면 80, ×10이면 320입니다. 작은 금액은 소수 부분을 그대로 표시합니다.

## 5. 조기 납부와 마지막 납부

플레이어가 확인한 규칙은 **월세 차감 후 잔액 이월**입니다. 충분한 보유금이 있으면 첫 번째 근무 후에도, 마지막 근무 후에도 월세를 낼 수 있습니다.

- 조기 납부: 월세를 차감하고 잔액·스킬을 유지한 채 다음 단계로 이동합니다.
- 남은 기회 활용: 돈을 강화에 쓰거나 다음 근무에서 더 벌 수 있습니다.
- 다음 단계: 남은 기회를 버리고 새 5회 기회를 받습니다.
- 마지막 기회: 월세가 충분하면 납부할 수 있습니다. 강화 화면도 열 수 있지만 구매 후 잔액이 월세보다 적어지는 경우는 차단합니다.

납부 가능한 상태는 퇴근 수입 정산 후입니다. 보유금이 부족한 월세 납부와 기회를 모두 쓴 뒤의 추가 근무는 거절합니다.

예: 1단계 보유금 184.5에서 월세 160을 내면 **24.5를 유지**하여 2단계로 진입합니다. 이동 스킬 레벨도 유지하고, 2단계는 5층·30초·월세 273·새 기회 5회로 시작합니다.

## 6. 퇴근 룰렛

플레이어가 선택한 구성은 **동일 크기 21칸: ×2 10칸, ×0 10칸, ×10 1칸**입니다.

| 저장·추첨 슬롯 ID | 결과 | 지급 | 확률 |
| --- | --- | --- | --- |
| 0–9 | ×2 | 이번 근무 수입 두 배 | 10 / 21, 약 47.62% |
| 10–19 | ×0 | 이번 근무 수입 전액 손실 | 10 / 21, 약 47.62% |
| 20 | ×10 | 이번 근무 수입 열 배 | 1 / 21, 약 4.76% |

룰렛의 대상은 **이번 근무 수입만**입니다. 기존 보유금은 보호합니다. 근무당 한 번만 선택하며 그대로 받기를 선택한 후 룰렛을 돌릴 수 없습니다. 수입이 0이면 룰렛 버튼을 비활성화하고 그대로 받기로 정산합니다.

### 정산 메인 화면과 별도 룰렛 창

퇴근 후 기본 화면은 월세 장부와 수입을 보여 주는 **메인 정산 화면**입니다. 휠은 이 화면에 포함하지 않습니다. `룰렛 창 열기`를 누르면 별도 팝업이 약 **0.4초** 동안 페이드·확대·이동하며 등장합니다. 창 열기는 추첨이나 수입 소비를 수행하지 않습니다. 준비 상태에서 돌아가기 또는 ESC를 누르면 미정산 수입을 유지한 채 메인 정산 화면으로 돌아갑니다.

창 안에서 `이번 수입 걸고 돌리기`를 누르면 모델은 균등한 슬롯 추첨과 정산을 먼저 수행하며, 로컬 저장을 완료한 뒤 연출을 시작합니다. 모델의 슬롯 ID와 지급 규칙은 위 표대로 유지합니다. 시각적인 휠 위치만 **×2, ×0, ×2, ×0 … ×2, ×0, ×10** 순서로 재배치합니다. 21개 슬롯을 일대일로 대응하므로 확률·보상·중복 지급 방지 규칙은 변하지 않습니다.

### 회전 연출

| 순서 | 구간 | 시간 | 화면 피드백 |
| --- | --- | ---: | --- |
| 1 | 수입 걸기 | 0.9초 | 이번 수입 티켓이 휠로 이동하며 작아짐, 중심과 테두리가 맥동 |
| 2 | 가속 | 0.75초 | 휠이 점차 빨라지고 포인터 반동·틱 소리가 시작됨 |
| 3 | 빠른 회전 | 1.1초 | 휠 고속 회전, 순환하는 테두리 조명과 배경 긴장도 유지 |
| 4 | 감속 | 3초 | 저장된 실제 결과를 향해 부드럽게 감속, 간격이 벌어지는 틱과 포인터 반동 |
| 5 | 결과 공개 | 0.65초 | 결과 칸 강조, 배수·지급액 공개와 파동. ×10일 때 금색 광선 추가 |

돌리기를 누른 뒤 결과 상태에 도달하기까지 합계는 약 **6.4초**입니다. 팝업 등장 0.4초는 별도입니다. 모든 결과에 같은 3초 감속 규칙을 사용하며 포인터가 저장된 결과 칸 중심을 가리킵니다. 배경 음악은 긴장도에 따라 부드럽게 낮아지고, 원본 저음 펄스와 기존 효과음을 재사용한 틱으로 회전을 보조합니다.

준비·가속·회전·감속·결과 공개 중에는 다른 정산·납부·강화·다음 근무와 창 닫기를 막습니다. 결과 공개가 끝나면 `결과 확인하고 정산으로`로 돌아갑니다. 뒤의 메인 정산 화면은 팝업을 닫기 전까지 기존 잔고 표시를 유지하므로 저장된 지급액이 연출 전에 노출되지 않습니다. 복귀한 뒤 갱신하며 추가 지급하지 않습니다.

이미 저장된 결과를 불러오면 다시 추첨하지 않습니다. 필요하면 결과 창을 다시 열어 저장된 결과 칸에 바로 정렬하여 확인할 수 있습니다.

룰렛 결과로 받은 돈까지 합친 뒤 마지막 기회의 월세 충족 여부를 판단합니다.

## 7. 파산과 재시작

다섯 번째 근무의 정산 후 보유금이 월세보다 적으면 `Bankrupt` 상태로 전환합니다. 여섯 번째 근무, 월세 납부, 강화 구매가 불가능합니다.

파산 화면에서 **1단계부터 다시 시작**을 선택하면 다음을 초기화합니다.

- 단계: 1단계
- 보유금·미정산 수입: 0
- 스킬: 모든 레벨 0
- 건물: 3층, 모든 전등 새로 공급
- 기회: 새 5회
- 시간: 30초

화면을 닫아서 계속하거나 초기화 없이 다시 시도하는 경로는 제공하지 않습니다. 재시작 버튼을 눌렀을 때 새 경력을 시작합니다.

## 8. 저장과 버전 구분

현재 런타임 저장 키: **`LightsOut.Rent.v3`**. JSON 복사본: **`Application.persistentDataPath/lightsout-rent-save.json`**.

외부 런타임 저장에는 월세 모델과 플레이어 위치를 담습니다. 모델 내부에는 단계, 기회, 시간, 현재 상태, 이번 수입, 정산 여부, 룰렛 슬롯·배수·사용 여부, 난수와 방·스킬·잔고·전파 상태를 기록합니다. 불러올 때 상태 간 모순이나 유효하지 않은 금액·기회·결과를 거절하며 유효 상태를 일부만 덮어쓰지 않습니다.

예전 이동 버전 `LightsOut.Movement.v2`와 클릭 버전 `LightsOut.Save.v1`은 별도 키로 유지합니다. 과거의 300층 진행을 월세 단계로 자동 변환하지 않습니다. 로컬 저장이며 서버 저장과 변조 방지 기능은 이번 범위에 없습니다.

## 9. 검증 기록

### 독립 모델 검사

이전 월세 MVP에서 **기존 이동 11개 + 월세·시간·룰렛 15개 = 26개 통과, 실패 0개**를 확인했습니다. 이번 별도 룰렛 팝업 수정에서도 기존 월세·시간·룰렛 모델 검사 **15개가 회귀 검사로 통과했으며 실패는 0개**입니다. 검사 메뉴는 다음과 같습니다.

- **Lights Out → Run movement and vertical checks**
- **Lights Out → Run rent, timer and roulette checks**

신규 검사는 기회 소비, 시간 종료, 최초 건물의 느린 경로 소등, 미정산 수입 보호, 정산의 단일 실행, 정확한 21칸 구성, 기존 잔고 보존, 월세 차감·이월, 마지막 기회 납부와 파산, 강화 제한, 상태 저장 검증을 포함합니다. 검증용 독립 모델을 사용하며 플레이어의 저장 상태를 사용하거나 변경하지 않습니다.

느린 초기 소등 경로 검사는 기본 이동속도의 35%로 판정 경로를 순회하여 약 14.3초에 전체 소등했습니다. 30초 제한 안에 완료했으며, 실제 사람의 초보자 플레이 시간을 측정한 결과는 아닙니다.

### 최신 별도 룰렛 팝업 Play Mode 검증

메인 정산에 휠이 없는 상태와 실제 버튼을 통한 별도 팝업 열기·돌리기·정산 복귀를 확인했습니다. 준비 상태에서 창을 열기만 한 경우 모델 JSON은 불변이고, ESC로 정산에 복귀했습니다. ×2와 ×0을 교차 배치하고 ×10 한 칸을 추가한 21개 표시 위치는 저장 슬롯과 일대일로 대응했습니다.

검증용 상태에서 다음 결과를 확인했습니다. 이는 실제 게임을 해당 단계까지 성장시킨 시간 기록과 구분합니다.

| 검사 | 관측 결과 |
| --- | --- |
| 준비·회전 입력 잠금 | 결과를 숨기고 메인 보유금 표시 유지. ESC·T·월세·구매·재시작·다음 근무와 중복 돌리기 차단 |
| ×10 지급과 정지 | 수입 61.5 → 지급 615, 기존 보유금 100 → 715. 저장된 실제 결과 칸에 정지 |
| 마지막 기회의 ×0 | 기존 보유금 100 유지, `Bankrupt` 상태. 팝업을 닫을 때 실패 메인 정산 화면으로 전환 |
| 음량과 음악 복귀 | master 0에서 오디오 소스 4개 모두 음량 0. 연출 종료 후 정상 음악 음량 0.18 복귀 |
| 회귀·오류 | 월세 모델 검사 15개 통과, Unity 컴파일·실행 오류 0개 |

### 이전 월세 MVP에서 실제 회전 중 저장 복원

별도의 검증용 상태에서 슬롯 20의 ×10 결과가 나온 직후, 회전이 끝나기 전에 실제 저장 파일과 PlayerPrefs에 **정산 완료·보유금 50·슬롯 20·배수 10**이 기록된 것을 확인했습니다.

이 상태로 Unity **Stop → Play**를 수행한 후 아래를 확인했습니다.

- 정산 후 상태 `BetweenAttempts`, 사용 기회 1회, 보유금 50 복원
- 슬롯 20, 배수 10 유지
- 회전 상태 `IsSpinning=false`, 휠 각도 약 342.857°로 즉시 정렬
- 게임 일시 정지 `IsPaused=true`: 종료된 근무에 복귀하지 않음
- 재추첨 요청 거절

마지막 컴파일은 오류 0개로 성공했습니다. 이 검증은 전체 게임의 장기 밸런스나 고층 전체 수동 플레이 완료를 증명하지 않습니다.

최종 실행 콘솔 오류와 누락된 스크립트는 0개입니다. Unity AI 패키지의 Account API 연결 시간 초과 경고 1개는 게임 로직과 별도로 남아 있습니다. 검증용 저장 데이터는 작업 전 상태로 복원했으며 테스트 수입·강화를 남기지 않았습니다.
